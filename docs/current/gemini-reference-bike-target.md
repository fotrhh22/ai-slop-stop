# Gemini 자전거 고정 비교 목표 (2026-11-04 최신 결정)

Gemini AI 사용량은 계속 **토큰만** 기록한다. 토큰을 Wh로 환산하지 않는다.
자전거 체험에는 과거 로컬 GPU 시험에서 얻은 **0.3463 Wh = 346.3 mWh**를 모든 Gemini 참가자의
고정 비교 목표로 사용한다. 참가자가 목표를 직접 입력하지 않는다.

근거: [4090 실측 기록](../archive/2026-11-campaign/runpod-session-operations.md)의 2026-11-03 동일 이미지 비교 3회 평균.
RTX 4090, FLUX.2 Klein 4B BF16 생성 0.1590 Wh + Qwen3.5-4B INT8 판정 0.1873 Wh.
이 값은 생성+판정 **1세트의 고정 비교 기준**이며 Gemini의 실제/추정 소비 전력이 아니다.
Gemini 참가자의 시도 횟수에 곱하지 않는다. 오픈모델은 기존대로 참가자의 첫 PASS까지 실측 합계를 사용한다.

## 동작

- PASS 목록: 가장 최근 참가자를 맨 왼쪽에 표시한다.
- Gemini 참가자 선택: 목표 346.3 mWh 자동 표시, 읽기 전용.
- ×100 환산 발전량이 고정 목표에 도달하면 자동 종료하고 최종 영수증을 한 번 출력한다.
- 미달 수동 종료도 지원하며 같은 목표 대비 달성률을 출력한다.
- 웹/종이 영수증에 RTX 4090 실측 평균을 참조한 비교 기준임을 표시한다.
- 시뮬레이션 선택/API와 비교용 고급 연결 영역은 제거했다. USB/Bluetooth 중 선택한 연결만 표시한다.

## 적용

1. 이전 SQL 이후 아래 파일 전체를 Supabase SQL Editor에서 한 번 실행한다.
   `supabase/migrations/202611040004_gemini_reference_target.sql`
2. Render와 Vercel에 최신 main 배포. 새 환경변수는 없다.
3. 진행 중 계측을 마치고 Bike/프린터 프로그램을 재시작한 뒤 페이지를 새로고침한다.

SQL은 기존 **대기 중 Gemini 참가자**에도 고정 기준을 넣는다. 진행 중/완료된 이전 세션의 목표와
영수증은 바꾸지 않는다. 이 문서가 이전의 'Gemini 목표 없음·수동 종료' 안내를 대체한다.
운영 SQL·모델 생성·계측·물리 인쇄는 이번 구현에서 실행하지 않았으며 화면 점검도 생략했다.
