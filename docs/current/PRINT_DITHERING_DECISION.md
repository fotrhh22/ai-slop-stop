# PT-210 · Atkinson 선택 기록

최초 정리: 2026-11-13. 보완: 2026-11-14. GitHub 1a306e7의 코드/운영 문서·보관 비교 시안·2026-11-01 설치 기록을 대조하고, 사용자가 언급한 **악어 머리 비행기 이미지 비교**의 원본과 네 방식 비교 시트를 다시 확인했다. 비교 대상·조건·산출물·Atkinson을 적용한 후속 영수증은 보관 파일과 준비 코드로 확인된다. 당시 선택 사유를 기록한 별도 회의록이나 방식별 실물 평가표는 발견되지 않아, 아래 시안 관찰은 보관된 디지털 결과를 현재 다시 읽은 설명으로 구분한다.

## 선택 배경: 악어 머리 비행기 영수증

초기 비교는 임의의 풍경 사진이 아니라 **기존 챌린지의 악어 머리 비행기 성공 이미지**를 작은 영수증에 옮기는 과정에서 진행했다. `printer_bridge/prepare_test.py`는 사용자가 제공한 `AI SLOP STOP CHALLENGE.pdf`의 첫 페이지에서 첫 이미지를 추출해 `source-photo.png`로 보관했다. 같은 코드의 보관 영수증에는 성공 시각이 2026-10-19로 기재돼 있으며, 비교 시안과 설치 기록은 2026-11-01에 남아 있다. 영수증에 기재된 성공 시각과 프린터 비교 날짜는 구분한다.

원본은 맑은 하늘·구름 위에 은색 비행기, 기수를 대체한 악어 머리, 기체 아래 매달린 폭탄이 있는 컬러 일러스트다. 이 그림에서는 작은 크기로 줄인 뒤에도 **악어의 얼굴과 입, 날개·동체의 윤곽, 아래쪽 폭탄**을 구별할 수 있는지가 중요했다. 하늘·구름과 은색 동체에 중간 명암이 많아, 흑백 변환 후 배경의 점 패턴이 피사체를 가리지 않는지도 함께 볼 수 있었다.

이 같은 이미지에 네 방식을 적용한 비교물을 준비한 다음, Atkinson을 사용한 보관 영수증과 최종 레이아웃으로 이어졌다. 따라서 선택 경위는 **실제 챌린지 이미지로 흑백 표현을 비교하고, 작은 영수증에서 피사체의 형태를 구분하는 목적에 맞춰 Atkinson을 채택한 과정**으로 설명한다. 아래의 구체적인 표현 차이는 디지털 시안의 재관찰이며, 당시 실물에서 정량적으로 우수성이 입증됐다는 뜻은 아니다.

## 요구 조건

- PT-210, 58mm 용지에서 실제 인쇄 폭 384dots. 초기 비교 사진은 좌우 여백을 제외한 360dots. 최신 최종 영수증의 사진 폭은 232dots이며 비교 시트와 구분한다.
- 컬러 사진을 흑백 1bit 비트맵으로 변환. 한글·숫자·QR/텍스트는 별도로 선명하게 렌더링.
- 최종 인쇄 크기로 먼저 리사이즈한 뒤 디더링. 만들어진 도트 패턴을 다시 확대·축소하지 않음.
- 원본 및 DB 성공 이미지는 유지. 출력용 사본만 변환하며 모델 API를 추가 호출하지 않음.

## 비교 과정

1. 제공된 PDF에서 추출한 같은 악어 머리 비행기 이미지를 가로 360dots로 비율 유지 리사이즈하고, 밝기 1.0·대비 1.0으로 맞췄다.
2. 브라우저 실사용 `web/src/utils/thermal.ts`로 네 알고리즘을 각각 독립 적용했다.
3. 비교 시트와 ESC/POS 데이터를 만들고 비교 출력 작업을 1회 제출했다.
4. 이후 Atkinson을 적용한 최종 영수증 레이아웃을 준비·제출했고, 브라우저 기본값과 워커 렌더러에 Atkinson을 사용했다.

준비 도구: [`printer_bridge/dither_test.cjs`](../../printer_bridge/dither_test.cjs), [`printer_bridge/prepare_test.py`](../../printer_bridge/prepare_test.py). `prepare_test.py`가 만든 공통 `source.rgba`를 `dither_test.cjs`에서 읽어 네 알고리즘에 각각 전달하므로, 비교 중 생성 모델이나 프롬프트를 바꾸지 않았다. 이 준비 코드는 시안과 ESC/POS 파일을 만들며 자체적으로 인쇄 작업을 제출하지 않는다. 제출 이력은 설치 기록에서 별도로 확인한다.

## 보관된 디지털 시안에서 확인한 차이

| 방식 | 같은 사진에서 관찰한 표현 |
| --- | --- |
| Atkinson | 구름과 밝은 하늘의 흰 영역이 넓게 남아, 악어 얼굴·날개·어두운 동체 하부와 아래쪽 폭탄이 배경에서 구분됨. 은색 동체의 부드러운 중간 명암 일부는 줄어듦 |
| Floyd–Steinberg | 하늘·구름과 은색 동체의 중간 명암이 도트로 더 많이 이어짐. Atkinson보다 배경에도 점이 촘촘히 남는 모습 |
| Ordered Bayer | 규칙적인 격자 패턴이 하늘과 동체 전반에 나타나며, 사진의 윤곽과 별개로 반복 무늬가 눈에 띔 |
| Ordered Blue Noise | Bayer의 규칙 격자 대신 분산된 입자감으로 하늘·동체의 중간 명암을 표현함. 배경에도 입자가 남음 |

이는 저장된 PNG 한 장의 육안 관찰이다. 종이·열 농도·드라이버에 따른 출력 품질 순위를 뜻하지 않는다.

## 현재 선택을 설명하는 근거

악어 머리 비행기 비교에서 중요했던 것은 컬러 원본의 모든 명암을 보존하는 것보다, 좁은 영수증에서도 참가자가 생성한 피사체와 주요 형태를 알아볼 수 있도록 하는 것이었다. 밝은 배경 영역과 주 피사체의 윤곽을 분리하는 표현에 Atkinson 기본값이 부합한다. 중간 명암 재현을 최대로 유지하는 목적과는 절충이 있다. 소스의 Atkinson 커널은 오차를 6개 이웃에 각각 1/8만 전달하며 총 6/8을 확산한다. Floyd–Steinberg는 7/16·3/16·5/16·1/16으로 오차를 확산한다. 이 구현 차이와 보관 시안의 표현 차이를 함께 기록한다. Atkinson은 학습형 이미지 모델이 아니라 흑백 변환을 위한 오류 확산 알고리즘이다.

브라우저는 네 방식을 선택할 수 있고 워커는 Atkinson으로 고정돼 있다. 한 사진에서의 선택을 모든 사진·프린터에 대한 우수성으로 일반화하지 않는다.

## 확인된 것과 남은 것

- 설치 기록에 초기 연결·한글/QR 인쇄 성공의 사용자 확인이 있다.
- 초기 설치 기록의 4방식 비교 출력·최종 시안 확인은 당시 대기로 남아 있다. 이후 최신 운영 문서에는 캠페인과 PT-210 실물 출력 완료가 운영자 확인으로 기록돼 있다. 따라서 최종 출력 전체를 미확인 상태로 되돌리지 않는다. 네 방식별 실물 비교 평가표는 여전히 발견되지 않았다.
- 현재 브라우저 기본값: `web/src/components/Receipt.tsx`.
- 최신 GitHub 워커 변환: `printer_bridge/renderer.py`.
- 커널 일치 확인: `printer_bridge/test_worker.py`와 `web/scripts/test-thermal.cjs`.
- 프린터 드라이버 설치 출처·라이선스: [설치 기록](../../printer_bridge/setup/README.md).

추후 알고리즘별 실물 비교 평가를 추가하면 종이·농도·가독성 조건과 함께 이 문서를 갱신한다. 이번 작업은 실제 인쇄나 원격 배포를 실행하지 않았다.

## 초기 비교와 최종 운영 구분

초기 360dots 비교 시트는 알고리즘 선택 과정을 설명하는 자료다. 최신 최종 출력은 384dots 용지에 232dots 사진을 중앙 배치하고, 자전거 체험 종료 후 인쇄한다. 최신 행사 운영·모델·출력 내용은 [운영 기준](OPERATIONS.md)을 따른다.
