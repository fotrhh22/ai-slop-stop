## 결과 개요

실제 행사 구간에서 **AI 성공 영수증 15건**, **이미지 생성 21회·판정 17회**, **자전거 체험 종료 15건**을 확인했다. 자전거 종료 15건은 서버 저장값과 Mac의 원시 계측 표본을 대조했으며, 각각 최종 인쇄 작업 1건의 `SENT`·CUPS ID·로컬 출력 파일·journal을 확인했다. 운영자는 실물 출력을 포함한 행사 진행 완료를 확인했지만, `SENT` 자체는 종이 배출 센서의 확인이 아닌 CUPS 접수 상태다.

이미지 생성의 GPU 소비 에너지는 **1회 평균 0.291067Wh**, 판정은 **1회 평균 0.165008Wh**였다. 구간 내 호출 전체의 GPU 소비 에너지는 **8.917542Wh**다. 자전거 15건의 원본 실측 합계는 **80.225778mWh = 0.08022578Wh**, 행사 환산 합계는 그 100배인 **8.022578Wh**다.

이 수치는 기록이 남은 챌린지·세션 건수다. 사람의 신원을 수집해 중복 제거한 고유 방문객 수나 만족도·행동 변화 지표로 해석하지 않는다.

### 전력과 에너지 계산

```text
현재 전력 W = 전압 V × 전류 A
원본 에너지 Wh = Σ[(이전 W + 현재 W) / 2 × 표본 간격 초 / 3600]
체험 환산 에너지 Wh = 원본 Wh × 100
환산 달성률 % = 환산 Wh / 해당 참가자의 AI 목표 Wh × 100
```

실측 합계와 세션 경과 시간 합계로 계산한 가중 평균 출력은 **0.742W**다. 세션 평균의 단순 평균은 **0.716W**, 가장 큰 전력 표본은 **1.798W**였다. 이전 시험에서 사용한 0.55W는 대표 가정값이고, 이번 현장 값을 일괄 0.55W로 대입하지 않았다. 이 출력은 VOLT1-CD·배선·부하의 해당 운전 조건에서 전달된 값이며 발전기 최대 능력을 뜻하지 않는다.

## 6. 출력 결과와 복구 사례

15세션에 인쇄 작업 17개가 연결됐다. 최종 상태는 **SENT 15개, FAILED 2개**다. S03에서 **13:38:09·13:43:13 `RENDER_FAILED`**가 기록됐고, **13:45:04 생성된 후속 작업은 SENT**로 남았다. 실패 작업을 별도 참가자나 추가 출력 성공으로 세지 않았다. 오류 코드만으로 실패 원인을 더 구체적으로 단정하지 않는다.

각 최종 작업에는 CUPS 작업 ID가 있으며, 로컬 journal의 SENT·ACK와 같은 ID가 연결돼 있다. 대응 PNG와 ESC/POS 파일도 모두 존재한다. 이 자료는 출력 전송의 근거이며 프린터가 실제로 종이를 몇 장 배출했는지 자동 감지한 값은 아니다.

당일 저장 PNG 높이는 **1456~1793도트**였다. 8도트/mm와 현재 ESC/POS의 밴드 올림·마지막 약 90도트 급지 가정으로 계산하면 약 **19.4~23.6cm**다. 이는 코드 기반 예상치이며 자로 잰 길이는 아니다. 앞서 안내한 19.7cm는 고정 예시 기준으로, 실제 행사에서 긴 프롬프트·통과 이유까지 모두 20cm 이내였다는 의미가 아니다.

## 7. 해석과 활용 범위

이 구간에서 이미지 생성·판정 → 영수증·참가자 등록 → 자전거 실측 → 서버 저장 → 인쇄 전송까지 이어지는 실제 운영 기록을 확인했다. 자동 종료뿐 아니라 미달 수동 종료와 렌더 실패 후 복구도 발생했다. 기록은 실제 사용 사례이며, 처리량 한계·장시간 장애율·참가자 만족도·캠페인 후 AI 사용 감소를 검증한 통계는 아니다.

**원본 발전량과 ×100 환산값은 반드시 구분한다.** 환산값이 AI 목표에 도달한 것은 체험 진행 조건을 만족한 것이며 GPU 서버를 자전거로 구동하거나 실제 소비 전기를 상쇄했다는 뜻이 아니다.
