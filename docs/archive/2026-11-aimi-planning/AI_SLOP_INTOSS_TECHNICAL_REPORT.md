## 2. 채택을 제안하는 구조

```text
앱인토스 WebView
  React + TypeScript + 공식 SDK/TDS
  ├─ 홈·개선기·추천·정원·소셜
  └─ 공통 게임 코어 + 길 건너기 / Temple Run / 다이노
       │ HTTPS + 서버 세션
Node.js / TypeScript / Fastify (Render)
  ├─ 토스 로그인 서버 연동
  ├─ 게임 기록·시도 제한·조건 판정·대표 이미지 조회
  ├─ EP·구매·보유·정원·친구 트랜잭션
  ├─ 개선·질문 분석 작업 → Gemini
  └─ 추천 엔진 → 저장된 가격·벤치마크 스냅샷
       │
Supabase PostgreSQL + Storage

콘텐츠 제작 CLI → 생성·검수 → 예약 콘텐츠 등록
GitHub Actions → AA/OpenRouter 수집·검증 → 활성 스냅샷 교체
```

모델 추천은 공개 근거·자체 품질 제약 아래 비용 최소화하는 코드다. 실제 추천 대상 모델을 모두 호출하지 않는다. 일일 과제는 예약 DB 조회이며 매일 앱 배포하지 않는다. 이미지 생성·거리 계산은 사전 제작 단계에만 둔다.

## 3. 구현 경계

- 프론트: 선택·미리보기·시트·팝업·게임 렌더링·임시 편집 상태.
- API: 계정 권한·콘텐츠 버전·가격·판정·사용자 한도·보상 확정·원문 분석.
- DB: 원장·동시성·멱등성·보유권·관계·버전 보존.
- LLM: 개선안·조건 추가 예시·관련 팁·질문 분류·제작용 후보. 게임 점수·EP·실시간 이미지 생성에는 사용하지 않음.
- 운영 스크립트: 모델 스냅샷과 콘텐츠 발행. 사용자 요청 처리와 별도 실행.

공유 계약·테이블·API·거래 경계·완료 기준·결정 필요 항목은 [통합 명세 10~13절](AI_SLOP_INTOSS_PROTOTYPE_SPEC.md#10-서버dbapi-계약)을 따른다. 개발 전환 시 해당 문서를 담당자에게 전달하고 API 스키마부터 합의한다.
